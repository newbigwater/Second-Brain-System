## 00. 목적

본 문서는 `04. Agent` 폴더를 “설계 레벨”에서 설명한다.  
초급자도 아래 질문에 답할 수 있게 하는 것이 목표다.

- `04. Agent`는 무엇을 담는가?
- `03. Operation System`과의 관계는 무엇인가?
- Role Rule은 무엇이며, 무엇을 할 수 있고 무엇을 하면 안 되는가?
- 새 Role을 만들 때 어떤 파일을 복사/작성해야 하는가?
- `04. Agent`의 표준 폴더/파일 구조는 어떻게 생겼는가?

---

## 01. 핵심 개념 3개(초급자용)

### 01.01. OS(Operation System) = 공통 “헌법 + 실행 엔진”

- OS는 “모든 작업”에 공통으로 적용되는 규칙이다.
- 예: 거짓 생성 금지, 불확실성 표기, 입력 누락 금지, 검증 절차, 산출물 출력 모드 등

### 01.02. Agent(Role) = 업무별 “플러그인(확장 규칙)”

- Agent는 특정 업무 역할(Role)에서만 필요한 추가 규칙을 정의한다.
- 예: “개인 프로젝트 관리”, “문서 설계”, “코딩”, “번역” 등

### 01.03. 가장 중요한 원칙: “OS를 약화할 수 없다”

- Role은 OS 규칙을 “확장(추가)”할 수는 있지만,
- OS의 불변 규칙을 “완화/무력화/재정의”할 수 없다.

---

## 02. 설계 원칙(Design Principles)

### 02.01. 역할 분리

- `03. Operation System`: 공통 규칙(불변/절차/검증/산출)
- `04. Agent`: Role 전용 확장 규칙(추가 제약/추가 검증/추가 템플릿)

### 02.02. 충돌 해결(Conflict Resolution)

충돌 시 우선순위는 아래를 따른다.

- OS Layer 0 → Layer 1 → Layer 2 → Layer 3 → Layer 4 → Role 확장 규칙

### 02.03. 검증 가능성

Role에 추가하는 규칙은 “검증 가능한 형태”여야 한다.

- 좋은 예: “요구사항 매핑 표가 존재해야 한다”
- 나쁜 예: “더 좋은 느낌으로 작성한다” (검증 불가)

## 03. `04. Agent` 표준 구조(안)

`04. Agent`는 아래 구조를 표준으로 삼는다.

```text
04. Agent/
  _MOC_.md
  readme.md
  00. Template/
    Role Rule Template.md
    Persona Template.md
  01. <Role Name>/
    Role Rule.md
    (선택) Persona Profile.md, Validation Checklist.md, Domain Knowledge.md ...
  02. <Role Name>/
    ...
    (선택) ...
  90. Shared Resources/
```

### 03.01. `readme.md` (개요)

- “이 폴더는 무엇을 저장하는가”
- “OS는 어디에 있고, Agent는 무엇을 할 수 있는가/없는가”

### 03.02. `_MOC_.md` (목차/인덱스)

- `04. Agent`의 “진입점” 문서다.
- 존재하는 Role 목록과 템플릿 파일로의 링크를 모아둔다.
- **Active Roles** 섹션은 `update_agent_moc.py`로 디스크 구조에 맞춰 자동 갱신할 수 있다(매뉴얼: `01. Doc/02. Manual/update_agent_moc - 사용법.md`).

### 03.03. `00. Template/` (템플릿)

- **Role Rule Template.md**: 새 Role을 만들 때 **복사해서 시작하는 표준 틀**이다. 필수 구성: Role 정의(누구/무엇을/어디에 적용), OS 상속 선언(강제), 확장 지점(추가 제약·검증·템플릿), 충돌 해결 우선순위, Role 전용 DoD(완료 조건).
- **Persona Template.md**: Persona(역할별 세부 페르소나) 특화 템플릿이다(선택).

### 03.04. `<Role Name>/Role Rule.md` (Role 핵심 규칙)

Role 1개당 최소 1개 존재한다.

- 역할의 적용 범위
- OS 상속 선언
- Role만의 추가 제약/검증/템플릿
- 완료 조건(DoD)

## 04. Role이 할 수 있는 것 vs 하면 안 되는 것

### 04.01. 할 수 있는 것(Extension Points)

Role은 아래 3가지 방향으로만 확장한다.

- 추가 제약(Constraints)
  - 예: “민감 정보는 필요한 항목만 구조화”, “문서 변경 시 영향 범위/롤백 포함”
- 추가 검증(Validation Hooks)
  - 예: “문서 간 용어 충돌 0건”, “인덱스 최신”
- 추가 산출물 템플릿(Output Templates)
  - 예: “의사결정 메모 템플릿”, “주간 회고 템플릿”

### 04.02. 하면 안 되는 것(금지)

- OS 규칙 약화/무력화/재정의
- 입력을 요약으로 대체하도록 허용하는 규칙 추가
- 검증 불가능한 감성 기준 추가
- 참조 전용(레거시) 영역의 경로를 OS/Agent 문서에서 참조

## 05. 새 Role을 추가하는 표준 절차(초급자용)

### 05.01. 폴더 생성

예시:

- `04. Agent/03. My New Role/`

### 05.02. 템플릿 복사

- `04. Agent/00. Template/Role Rule Template.md`를 복사해
- 새 폴더에 `Role Rule.md`로 저장한다.

### 05.03. 템플릿 채우기(필수)

- Role Name / Applies To / Audience(또는 Domain)
- OS 상속 선언
- 추가 제약(최소 1개 이상이 “명확한 문장”으로 존재)
- 추가 검증(가능하면 체크리스트 형태)
- 필요 시 출력 템플릿(섹션/표 구조)
- DoD(완료 조건)

### 05.04. `_MOC_.md`에 Role 반영

- 새 Role을 **Active Roles**에 반영한다.
  - 수동: `_MOC_.md`를 열어 해당 Role 한 줄(폴더명·설명·하위 항목)을 추가한다.
  - 자동: `update_agent_moc.py --write`로 **Active Roles** 섹션 전체를 디스크 기준으로 갱신한다(매뉴얼: `01. Doc/02. Manual/update_agent_moc - 사용법.md`).

## 06. 예시 Role(설계 예)

### 06.01. 문서 설계/정합성 강화 Role(예)

- 목적: 규칙/문서/템플릿 설계 및 문서 간 정합성 강화
- 특징: “검증 가능 문장(yes/no)” 중심, 정합성/인덱스 최신/금지 참조 점검을 강조

### 06.02. 개인 프로젝트 통합 관리 Role(예)

- 목적: “나” 관련 모든 영역을 통합 관리
- 특징:
  - 카테고리(Health/Money/Relationships/...)로 분류
  - 의사결정 지원(옵션/기준/리스크/Next Actions)
  - 민감 정보 최소 출력(필요 항목만 구조화)

## 07. 완료 조건(DoD)

- `04. Agent/_MOC_.md`에서 모든 Role에 접근 가능하다.
- 모든 Role 문서가 “OS 상속 선언”을 포함한다.
- 모든 Role 확장 규칙이 “추가”만 포함하며, OS 약화를 시도하지 않는다.
- OS/Agent 문서에서 참조 전용(레거시) 영역 경로 참조가 0건이다.
